# 体验版发布与更新

## 选最省操作的路径

| 情况 | 选择 |
| --- | --- |
| 本机开发者工具已安装/可登录 | 官方命令行预览、上传、部署；Ego Browser 操作公众平台 |
| 已有妥善保管的代码上传密钥，需要无人值守上传 | 官方 `miniprogram-ci`；后台设置仍需核对 |
| 已有上传密钥，需要自动添加体验者 | 官方 `miniprogram-mp-ci` 提交添加申请，管理员手机确认 |
| 工具不可用或平台阻止自动操作 | 先排查实际错误；仅把无法代办的准确一步交给用户 |

不要为了少点一次按钮强迫新手先准备服务器、持续集成平台和上传密钥。没有官方支持的“设为体验版”命令时用后台页面，不调用猜测出来的私有接口。所有参数以当前工具帮助和[官方资料](official-sources.md)为准。

## 首次发布

1. **核对目标与前置状态。** 确认工程的真实小程序编号、目标后台账号、操作权限和云环境。记录本次版本及改动摘要。后端有变动时先完成部署与真实调用；构建型工程先产生微信可上传代码。
2. **开发验证。** 检查本次影响的功能。需要预览时生成开发预览码，明确标注“开发预览”，由有对应权限的账号验证。给配偶交付要继续后续体验版步骤。
3. **上传。** 使用下面脚本或当前官方工具上传。检查退出码、错误输出和上传信息；错误时查实际原因，不连续盲重试。超时或结果不明先查询后台是否已经上传，再决定是否重试。
4. **后台确认。** Ego Browser 打开 `https://mp.weixin.qq.com/`，复用登录，核对目标小程序。进入当前页面里的版本管理，在开发版本中找到本次版本号、上传时间和备注对应的记录。不能只挑列表第一项。
5. **设为体验版。** 对目标记录执行“设为体验版”等当前等价操作。核对已有体验版是否被替换，记录实际标记及入口。该动作属于已授权的体验版发布范围，不再额外问一次。不要误点提交审核或正式发布。
6. **体验成员。** 在成员管理找到体验成员，检查目标微信号是否已有查看体验版权限。需要时添加用户指定的微信号，仅授予体验权限。若管理员需扫码或手机确认，准备好申请后让本人做这一步，再查生效结果。不要把展示名或手机号猜作微信号。
7. **入口与二维码。** 配置已存在的页面路由和正确参数，下载当前体验版二维码到私有目录，核对它来自体验版页面。普通入口优先稳定路由；含业务邀请码的入口必须同时检查码对应业务资格。记录页面显示的二维码期限，不猜有效天数。
8. **实际交付。** 在聊天中展示图片。让目标体验者用自己的微信扫码，只做一次核心操作，例如“扫码后点加入，再新增一条测试待办”。Codex 自己检查后端结果。手机上授权、进入成功、数据保存或双方同步未取得结果时，分别标为待验证，不提前宣布全部完成。

## 官方开发者工具命令

由 Codex 执行。先对实际安装运行 `cli -h` / 对应子命令 `-h`，再用需要的参数。不要把例子中的路径和环境当成用户真实值。

附带 Python 3 脚本（不依赖第三方包）覆盖常用动作：

```bash
python3 scripts/devtools.py inspect --project /absolute/project
python3 scripts/devtools.py preview --project /absolute/project --output /absolute/private-output/preview
python3 scripts/devtools.py upload --project /absolute/project --version 0.1.0 --desc '首次体验版' --output /absolute/private-output/upload-010
```

脚本在 `--output` 下创建独立运行目录，避免旧二维码或上传结果被误认作本次结果；如果创建在项目内，先添加 Git 和上传打包排除。自动查找常见 macOS 路径；其他路径/Windows 通过 `--cli` 指定。`inspect` 只检查本地配置，不登录、上传或验证云端；预览和上传才调用真实开发者工具。Windows `.bat` 命令请直接使用官方帮助，脚本仅支持可直接执行的 CLI 文件。

底层官方常用命令（macOS/Linux shell 示意）：

```bash
# WX_CLI 与 PROJECT_DIR 由 Codex 根据实际路径设置；不要复制占位值运行。
"$WX_CLI" islogin
"$WX_CLI" open --project "$PROJECT_DIR"
"$WX_CLI" build-npm --project "$PROJECT_DIR"
"$WX_CLI" cloud env list --project "$PROJECT_DIR"
"$WX_CLI" cloud functions list --env "$WX_ENV_ID" --project "$PROJECT_DIR"
"$WX_CLI" cloud functions deploy --env "$WX_ENV_ID" --names "$FUNCTION_NAME" --remote-npm-install --project "$PROJECT_DIR"
"$WX_CLI" cloud functions info --env "$WX_ENV_ID" --names "$FUNCTION_NAME" --project "$PROJECT_DIR"
```

只在确需 npm 构建时执行 `build-npm`；云函数部署后还要检查返回详情和函数实际调用。登录和二维码输出参数以当前 `login -h`、`preview -h` 为准。

## 可选：官方 CI 工具

`miniprogram-ci` 负责上传/预览等；`miniprogram-mp-ci` 负责成员管理。它们不是同一个包，不能把上传结果当体验版已设置。读取 [ci 官方文档](https://developers.weixin.qq.com/miniprogram/dev/devtools/ci.html) 和 [成员管理官方文档](https://developers.weixin.qq.com/miniprogram/dev/devtools/miniprogram-mp-ci.html) 后，按实际环境安装所需包、记录实际版本。

管理员在官方后台生成代码上传密钥，配置可信出口 IP 白名单。密钥仅存用户私有文件或密钥管理设施，不写入聊天、前端、公开仓库或命令日志。不为排错随意关闭白名单；也不为这个流程索要无关的 AppSecret。

以下仅是成员添加 API 的最小调用结构，`project` 必须按官方文档用当前项目和私有密钥构造；目标微信号来自用户，不能使用示例身份：

```javascript
const result = await ci.manageProjectMember({
  project,
  action: 'add_experiencer',
  robot: 1,
  member_list: [{ wechatid: targetWechatId }],
});
```

检查返回 `errCode`/`errMsg`；`80601` 表示成员已存在，应查权限现状而非重复添加。官方说明：调用成功后管理员会收到公众平台安全助手消息，**管理员确认后才生效**。因此分开记录“申请已提交”和“体验权限已生效”。不使用开发者/运营者权限作为体验权限的替代。

## 常见失败与最小排查

| 现象 | 先检查 | 不要做 |
| --- | --- | --- |
| 工具命令连不上 | 实际路径、服务端口、登录、当前子命令帮助 | 猜参数或连续重启 |
| 上传成功，手机仍旧版 | 后台目标版本、体验版标记、入口、手机重新进入后的版本 | 反复上传相同代码 |
| 对方提示无权限 | 扫的是不是体验版码、目标微信号、管理员确认是否完成 | 直接授予开发/管理权限 |
| 能打开但加入失败 | 业务邀请码资格、是否被新码撤销、服务端权限与调用阶段 | 认定微信体验权限正常就等于业务加入成功 |
| 页面空白/闪退 | 路由、运行错误、最近改动、云调用响应 | 先删除用户数据 |
| 云函数创建成功却调用失败 | 创建状态、实际代码、云端依赖、超时、目标环境 | 把外层 success 当作全部部署成功 |
| 只有模拟器正常 | 真机权限、基础库、域名、环境关联、真实微信身份 | 把跳过域名校验当成修复 |
| 通知点击进不去 | 消息打开的版本、页面路径、体验权限 | 假定总是打开正式版 |

卡在一个问题时按“收集证据 → 查官方说明 → 单点修复 → 对应验证”推进；无新证据不反复跑全量检查。缺少本人扫码或真实手机信息时继续完成独立工作，再留下明确的下一步。

## 后续更新

核对上次版本和修改范围，保留数据及成员。部署需要变动且兼容现有客户端的云函数；上传带新版本号的代码；后台确认最新目标版本仍为体验版；必要时更新二维码。即使平台可能沿用体验版选择，也要观察确认，不能假定会自动切换。

保留可恢复的代码版本和必要配置。恢复旧前端不等于数据库已回退，涉及结构变更需先准备兼容方案；不自动执行破坏性回退。

## 正式上线分支

用户明确要求正式上线后，先从当前账号后台和官方入口核实主体、类目、资质、名称头像、认证/备案、隐私与接口要求。Codex 准备材料草稿、修复检查结果、整理审核说明；用户提供真实资料及必要验证。任何新增费用先说明并取得选择，不把历史免费环境的状态当作未来保证。

按官方流程完成预览验证、上传、提交审核；等待真实审核结果，失败则修正具体问题。审核通过后按用户已授权范围发布并验证正式入口与服务端。不要为了交付体验版提前走这条分支，也不要宣称审核一定通过或承诺审核时间。
