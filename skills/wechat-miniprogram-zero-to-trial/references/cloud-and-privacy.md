# 云端、共享数据与隐私

只加载和实施当前产品需要的部分。无共享、无后台需求的工具不强制开通云服务。

## 云环境

先枚举已有环境和项目关联，确认目标小程序能访问该环境。优先复用已授权的正确环境；新建时可从微信开发者工具云开发入口开始。已有腾讯云侧环境需要根据官方指引核对账号关联，不能只把环境编号复制到前端就宣称接通。

开通前读取控制台套餐、免费期、额度、到期时间和续费设置。费用不确定时查官方并询问用户；禁止承诺永久免费，或未经授权购买、升级、打开自动续费。免费环境过期也可能影响体验版。

初始化时显式使用确认过的环境，核对云函数、数据库及存储都指向它。云函数先等创建完成，再检查代码上传、依赖安装和实际调用结果。顶层“成功”响应、资源已创建和函数代码已生效是不同证据。

按本次需求建立数据库、索引、函数、存储规则和必要触发器。只部署变化的函数。数据库或定时器配置不能假定会随前端代码上传自动发布。

## 多人共享与权限

- 身份从平台可信上下文/经过验证的登录凭据取得。客户端传来的姓名、角色或用户编号不能直接决定权限。
- 数据权限按产品确定。仅经云函数访问的集合可禁止客户端直接读写，再由函数校验成员身份；允许客户端访问的架构则设置并验证对应安全规则。不把全部集合设成公开读写来解决报错。
- 至少验证本人能做允许的操作、其他人不能越权、重复提交不重复记账。并发编辑或邀请兑换存在冲突风险时用事务或等效保护。
- **微信体验成员权限**解决能否打开小程序；**业务加入/邀请**解决能否访问共享空间，两项分别检查。
- 邀请有效期、一次性使用、新邀请是否撤销旧邀请由当前产品规则决定，不硬编码任何旧项目规则。入口预填邀请参数时允许修改，失效时留在可恢复页面。
- 不能把“生成邀请成功”写成“对方已加入”。以另一真实微信账号操作和服务端成员结果验证。

## 可选提醒

先在当前账号模板库核对实际开放的消息类型、类目、字段与资格，参照[订阅消息官方说明](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/subscribe-message-overview.html)。不要把普通一次性订阅的“保持选择”解释为无限发送；官方有其他消息模式，也不能假定当前账号都能用。

采用弹窗订阅时，在用户有效操作触发下请求授权；拒绝仍能保存核心内容。通知发送状态区分成功、明确失败与结果不确定，避免超时后盲目重发。记录发起请求的开发/体验/正式环境，按发送接口当前文档设置通知跳转版本，让体验者进入有权限的版本。

定时器配置后检查实际触发日志，再做一次用户同意的手机送达验证。不能用“调度存在”代替“通知已收到”。不为了测试给无关联系人发送消息。

若用户只要每天固定提醒，可提出手机日历方案并让用户选择；实施前核对日历 API、平台支持和隐私要求。成功添加后说明提醒由手机系统管理，不宣称小程序能读取或删除它无权管理的事件。

## 隐私和真机检查

根据真实收集的数据和实际使用接口准备隐私指引，补齐用户确认的联系方式。前端隐私授权、系统权限以及后台指引都要核对，不能因为是体验版就忽略。

把权限请求放在需要该功能的位置，拒绝时给出可继续的流程。对真正处理隐私数据的行为按当前官方要求实施，不将所有能力都笼统描述为只需“一次授权”。

真实云调用验证只使用必要的测试数据，记录测试产生的对象，按授权范围清理这些对象。不得删除用户历史、重置环境或放宽生产权限来验证。

相关入口见 [官方资料](official-sources.md)。运行时、数据库权限语法、触发器格式和 API 参数实施前再查对应当前官方文档。
