# 账号与开发

## 先识别实际起点

| 当前状态 | Codex 接下来做什么 | 用户最少需要做什么 |
| --- | --- | --- |
| 没账号 | 打开微信公众平台注册入口，解释主体差异，准备名称、简介、头像候选 | 确认主体，填写真实资料并验证 |
| 有账号，没工程 | 登录后台获取小程序编号和当前权限，创建工程 | 微信扫码登录 |
| 有工程，没发布 | 读取工程配置、构建方式、已有环境和发布记录，补齐差项 | 仅在登录失效或权限不足时授权 |
| 已有体验版 | 核对线上版本、目标体验者和当前故障，继续更新 | 必要的手机验收 |

官方入口：[微信公众平台](https://mp.weixin.qq.com/)、[微信开始指南](https://developers.weixin.qq.com/miniprogram/dev/framework/quickstart/getstart.html)。通过页面真实链接进入注册，不拼接带登录令牌的地址。

账号和资料：

1. 确认这是“小程序”账号，不是公众号；小程序编号取自目标账号后台，不能沿用示例编号。
2. 本人、配偶或企业谁持有账号由用户选择，Codex 不替用户决定主体。有现成账号时先复用。
3. Codex 可准备名称、简介、头像和与真实功能匹配的类目候选；遇到重名提供替代名称。联系方式、主体信息、资质资料必须来自用户，不能编造。
4. 根据账号后台实际提示核对认证、备案和类目要求，费用及开放能力以当前官方页面为准。体验版不能被承诺永远免费、永久有效或不受平台要求约束。认证与备案也不是同一件事。
5. 不为让亲友体验而擅自购买认证、注册公司、启用微信支付或公开上线。若必需，先解释具体阻塞和可选方案。

## 开发工具与工程

从[官方渠道](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)选择当前系统可用的稳定版。优先使用已有安装和登录；安装、打开工程、依赖安装由 Codex 完成。系统确需本人授权时只交接那一步。

命令行使用前检查“设置 → 安全设置 → 服务端口”。能用桌面工具完成时由 Codex 设置；不能时打开工具并告诉用户这一个开关的位置。无需为此把服务暴露到公网。macOS 的命令行为应用包内 `Contents/MacOS/cli`；Windows 为安装目录的 `cli.bat`。路径以实际安装为准。

原生简单工程通常含：`project.config.json`、小程序目录下的 `app.js/app.json/app.wxss` 和页面文件；如需云函数，再配置 `cloudfunctionRoot`。核对 `miniprogramRoot`、`appid`、`projectname`、页面路由与文件大小写。Taro/uni-app 等工程先执行现有构建流程，对生成的微信工程操作，不把源码目录误当上传目录。

开发要点：

- 原生代码不能照搬浏览器 DOM、localStorage 或只有 Node.js 服务端存在的模块。
- UI 同时处理首次使用、空数据、网络慢、保存失败、授权拒绝与重复点击。共享保存成功后才显示成功结果，失败保留输入。
- 单人本地存储要解释换设备和清理数据的影响；多人共享不能只做“名字切换”伪装不同微信身份。
- 金额、日期等业务按实际需求实现；涉及金额时避免浮点累计误差，涉及时间时明确时区与跨日行为。
- 下载依赖、构建 npm、检查包体限制、最低基础库兼容由 Codex 处理。不要为了发布随意升级整套依赖。
- 外部网络接口核对 HTTPS 与合法域名等平台要求；开发者工具中“跳过校验”不能作为手机可用证据。

## 本地工作记录建议

保存到私有工作目录并排除提交。只记录需要续做的信息：

- 使用者和核心验收动作；当前范围是开发、体验版还是正式上线。
- 目标小程序和云环境的本地配置引用；平台操作身份是否足够。
- 已完成阶段及证据位置；仍待用户扫码、填写或手机验证的事项。
- 最近代码版本、云函数变更、入口路由、二维码生成时间与页面显示的到期时间。
- 问题发生阶段、已查官方说明、下一次需要验证的假设。

不要保存密码、验证码、Cookie、上传密钥正文或身份证件。邀请码若必须临时保留，仅置于私有文件中，不进入普通诊断日志。
