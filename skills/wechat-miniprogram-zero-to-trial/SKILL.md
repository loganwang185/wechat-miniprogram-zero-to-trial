# 从零开发微信小程序并交付体验版

目标是让不懂代码的人拿到能在手机微信里使用的小程序。默认交付体验版；只有用户要求公开上线时才继续正式发布。适用于新项目，也适用于已有项目继续发布。不要把“流程说明”当成用户要求开发时的完成结果。

## 协作方式

- 用中文、短句和按钮名称沟通。首次出现 AppID 等名词时解释为“小程序编号”。不要要求用户打开终端、运行命令、编辑 JSON、找日志或部署云函数。
- 先读已有项目、会话和发布记录，能自己查到的信息自己查。首次缺信息时只问：想做什么、谁来用、有没有小程序账号；已知的不要重复问。先用已有信息推进页面和本地功能。
- 对真正影响产品的未定方案（是否多人共享、是否购买服务、账号归谁）给出通俗选项并询问。普通实现细节由 Codex 决定，不把技术选型变成用户作业。
- 用户授权“开发并发布体验版”后，继续完成这个范围内的开发、配置、上传、设置体验版和指定体验者管理，不在每个环节重复索要确认。仅有“帮我做个小程序”时，先完成可审阅结果，再明确对外发布范围。
- 需要本人验证时先打开准确页面、准备好可填写内容，再只交接眼前一个动作，例如：“请用管理员微信扫描右侧二维码，手机上点确认。完成后我继续。”管理员不是当前用户时说清楚谁来扫码。
- 登录密码、短信验证码、身份证件和人脸验证由本人在官方页面完成；不要求粘贴到聊天。平台不能代做的授权不伪装成已完成。
- 调用现有工具前先发现其真实能力。网站操作优先使用已安装的 **Ego Browser** 并先读它的 SKILL.md；同一任务复用一个浏览器工作空间。缺少浏览器能力时，先说明并配置可用工具；不要把浏览器代码写进小程序。微信开发者工具是桌面软件，使用官方命令行或可用的桌面操作工具，Ego Browser 只操作网站。
- 不确定的接口、限制、费用、类目和发布要求查当前官方资料；链接入口见 [官方资料](references/official-sources.md)。冲突时比较版本和适用账号，必要时问用户，不能猜。文档打不开就换官方入口或用浏览器读取，记录未核实项。

## 执行流程

### 1. 接续状态，确定最小可用版本

检查项目目录、AGENTS.md、Git 状态及已有账号/发布记录。已有 `.codegraph/` 时先使用 CodeGraph 定位代码，不自行建立索引。保留用户未提交修改。

把目标整理成几个可以实际验收的动作，例如“新增一笔、另一个人能看到、退出再打开仍存在”。简单单人离线工具可用本地存储；多人共享或换手机保留数据才需要服务端。沿用已有框架；从零的简单项目可选原生微信小程序，避免不必要的构建链。

在项目中保存一份简短的本地工作记录，例如 `.local/wechat-release.md`，并排除 Git 上传：阶段、已验证事项、未解决问题、版本、所用账号/环境的本地引用、下一步。二维码、邀请码、用户资料和密钥不得放入公开仓库。后续从这份记录续做，不反复注册或创建云环境。

### 2. 准备账号与开发环境

读取 [账号与开发](references/account-and-build.md)。Codex 负责进入注册页面、整理名称/简介/头像/类目候选、安装与配置开发工具、读取并核对小程序编号、创建工程和打开项目。用户只提供事实资料、选择账号主体及完成身份验证。等待账号步骤时可以并行推进不依赖账号的代码，但测试号和模拟数据不能作为体验版交付。

### 3. 完成代码和需要的服务端

先实现核心路径及空白、加载、失败、拒绝授权状态，再完善外观。不得用演示数据掩盖尚未接好的服务端。

需要云服务、多人共享、提醒或敏感接口时读取 [云端与隐私](references/cloud-and-privacy.md)。可使用已安装的 CloudBase 对应技能；没有插件时按官方文档使用开发者工具/命令行，不把插件作为无条件前置。Codex 负责部署、权限配置和错误诊断，用户只负责必要的开通授权及已说明费用的选择。

### 4. 验证可运行

只做与本次变化相关的检查：编译、关键业务规则、受影响页面和必要权限验证。首次发布走一遍核心操作；以后按变化缩小范围。不要反复跑全量测试。

开发者预览用于开发验证，另一个体验成员要用体验版验证。没有真实手机结果时记录“待手机验证”，不得用模拟器、假身份或后台无报错代替。

### 5. 上传并交付体验版

必须读取 [体验版发布与更新](references/trial-release.md)，按其中步骤完成：

**核对项目和云环境 → 上传代码 → 后台核对版本 → 设为体验版 → 配置体验成员并确认生效 → 下载体验版二维码 → 指定微信账号实际打开并验证核心功能。**

脚本 [devtools.py](scripts/devtools.py) 可检查工程、生成开发预览和上传代码；它不负责把版本设为体验版，也不证明云端可用。Codex 运行脚本，不把命令转交给零基础用户。

最终回复只给用户：本次版本、可扫码图片、现在需要点什么、确实存在的未完成项。二维码和详细诊断保存在用户自己的私有工作目录。若只到上传成功，明确说还没设为体验版；若另一个人的手机尚未验证，明确区分“后台已设置”与“已能使用”。

### 6. 更新与可选正式上线

已有体验版按同一发布记录更新，保留用户数据，先部署兼容旧客户端的服务端，再上传客户端。出错恢复范围只包含本次变化；清空数据库或旧本地数据不能作为常规排错手段。

只有用户要求正式公开给所有人使用时才进入 [正式上线分支](references/trial-release.md#正式上线分支)。公开 GitHub 源码与微信正式上线是两件事，不能互相视为授权。

## 完成判据

按实际证据记录，不能一概打勾：

- 目标开发版本在正确小程序后台可见，版本号与本次代码一致。
- 该版本已被设置为体验版，入口页面和参数正确。
- 指定体验者权限已经生效；没有顺便授予管理或开发权限。
- 交付的是体验版二维码，且独立检查业务邀请码是否有效。
- 涉及云服务的核心功能调用真实后端，已验证授权和数据保存。
- 至少目标体验者在手机上实际完成核心操作；未取得结果时保留待验证状态。
